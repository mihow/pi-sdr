We're building a signal-driven radio scanner on the `feat/scanner-v2` branch of `pi-sdr`. Read `docs/claude/sdr-scanner-reference.md` for prior art deep links. The hardware is an SDRplay RSP1A (6 MHz BW, 14-bit) on this x86_64 host, and an RTL-SDR Blog V4 on a Pi. The scanner should: capture wideband IQ via SoapySDR, sweep the spectrum with FFT power detection (no preset frequency list), auto-detect signals above noise floor, demodulate NFM/WFM/AM, detect voice with VAD, and stream audio to a mobile-first web UI. Run in Docker with `sdrplay_apiService` inside the container. Consider whether to build a custom UI or add a scanning mode to OpenWebRX+ — research both, propose 2-3 approaches with tradeoffs, and get my approval before writing code. The previous attempt (`feat/sdrplay-wip`) had working SDRplay Docker setup and AM demod but broken FM demod due to bad decimation at high sample rates — see reference doc section 8 for lessons.
